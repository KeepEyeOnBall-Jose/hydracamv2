01 / Contrast and control meaning

Help that can be seen and identified

Yellow help icons on pale settings rows were only 1.50:1 contrast. Informational text used a disabled gray, and the dialog’s yellow Close label was 1.63:1 against white.

Help and menu icons now use readable neutral colors. Settings controls carry their visible label into semantics, help buttons have tooltips, and the back button uses the platform’s localized label. Selected switches use black on yellow.

Dialog and navigation proof

The information dialog uses the theme’s readable action color and title scale, and scrolls when required. The old dialog behavior is traceable in 6e83866b:lib/services/alert_utils.dart; its earlier screenshot was overwritten during capture debugging, so it is not presented as a retained image.

02 / System appearance

Light and dark are complete themes

The app previously supplied only a light theme and hardcoded light surfaces. It now follows system appearance. Settings, session diagnostics, media states, dialogs and supporting panels use contextual colors. Camera canvases and app chrome remain black.

Secondary text on the muted light surface rises from 4.23:1 to 6.42:1; hint text rises from 2.46:1 to 6.42:1. Error containers use their own foreground colors. Critical battery and storage alerts use opaque red with white text.

03 / Accessibility settings

Large text without clipped controls

A 320-point-wide settings test at 200% text exposed a 106-pixel overflow in the Capture Settings badge. The badge now wraps; dropdowns expand within available width and allow variable item height. Settings rows stack when text grows.

The countdown also respects Reduce Motion: its pulse stops while timing and completion continue. This behavior has a regression test; no before/after motion recording is claimed.
